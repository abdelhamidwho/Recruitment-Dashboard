# Phase 1 Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the single-user prototype's foundations — add user accounts with login, collapse per-search candidate rows into one permanent record per LinkedIn profile, and build the normalisation layer that turns raw scraped text into country, region, education level, field of study, experience years, industry, and language level.

**Architecture:** A new `src/lib/normalize/` module of pure, individually tested functions derives every dimension from raw profile text. The Prisma schema gains `Person` (unique on `profileUrl`) plus a `SearchRunPerson` join carrying each run's score, replacing the old per-run `Candidate` table. Authentication is email/password with scrypt hashing and server-side sessions in the database, enforced by a single `requireUser()` helper; `proxy.ts` only does a cheap cookie-presence redirect, since Next.js 16 proxy must not touch shared modules or the database.

**Tech Stack:** Next.js 16.3 (App Router, Turbopack), React 19, Prisma 7 with the `better-sqlite3` driver adapter, SQLite in WAL mode, Vitest for unit tests, `node:crypto` scrypt for password hashing (no new runtime dependency).

## Reference notes for the implementer

Read these before starting. They are non-obvious and will cost you hours if missed.

- **This Next.js is version 16.** `middleware.ts` is deprecated and renamed to `proxy.ts` (root-level export named `proxy`). `cookies()` from `next/headers` is **async** — `const jar = await cookies()`. Setting or deleting a cookie only works inside a Route Handler or Server Function, never during Server Component render. Local docs: `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/proxy.md` and `.../04-functions/cookies.md`.
- **Proxy must not import the database.** The docs state proxy is invoked separately from render code and may be deployed to a CDN; it must not rely on shared modules or globals. So proxy checks only that the session cookie exists. The real session lookup happens in `requireUser()`.
- **This is Prisma 7.** The datasource block in `prisma/schema.prisma` deliberately has no `url` — the URL comes from `prisma.config.ts`. The client is generated by the `prisma-client` generator to `generated/prisma` (repo root, not `src/`), and is imported as `../../generated/prisma/client`. Run `npx prisma generate` explicitly after every `migrate` — Prisma 7 does not do it for you.
- **SQLite has no enum and no JSON type.** Every enum-like column (`User.role`, `JobCandidate.stage`, `SearchRun.status`) is a `String`, and every structured value is a JSON `String`. Validation happens in application code.
- **There are no migrations yet.** `prisma/migrations/` does not exist; `dev.db` was created by `db push`. Task 8 baselines the existing database before any schema change, so nothing is ever reset. **Never run `prisma migrate reset` or `db push --accept-data-loss` in this project** — they destroy data and require explicit user consent.
- **Known bug you are fixing, not introducing:** in mock mode `startRun()` returns the literal string `"mock-run-id"` for every run, and both `src/app/api/search/[runId]/route.ts` and `SearchBuilder.handleSearch` address runs by that Apify `runId`. `findFirst({ where: { runId } })` therefore always returns the *first* run ever created, so every mock search silently shows the first search's results. Task 18 re-keys these routes on `SearchRun.id`.

```ts
import { canonicalCountry, regionForCountry, type Region } from './regions'

export interface NormalizedLocation {
  raw: string | null
  city: string | null
  country: string | null
  region: Region | null
}

const NOT_A_PLACE = new Set(['remote', 'worldwide', 'anywhere', 'global', 'n/a', '-'])

/**
 * US state lookup: two-letter codes are exhaustive (all 50 states plus DC);
 * full-name spellings are only the common ones seen in profile data, with
 * abbreviations covering the rest. This partial list is deliberate, not unfinished.
 *
 * Note: When combined with parenthesis stripping, `"New York (NY)"` strips to `"New York"`,
 * which is in this set, so it resolves to country='United States' with city=null.
 * This narrow interaction only affects the few full-name US states that are also city names
 * (New York, Washington, Georgia) when written with parenthetical abbreviations.
 * The ordinary "New York, NY" form is unaffected and still works correctly.
 */
const US_STATES = new Set([
  'al','ak','az','ar','ca','co','ct','de','fl','ga','hi','id','il','in','ia','ks','ky','la','me',
  'md','ma','mi','mn','ms','mo','mt','ne','nv','nh','nj','nm','ny','nc','nd','oh','ok','or','pa',
  'ri','sc','sd','tn','tx','ut','vt','va','wa','wv','wi','wy','dc',
  'california','texas','new york','florida','washington','massachusetts','illinois','georgia',
  'virginia','colorado','arizona','oregon','michigan','ohio','north carolina','new jersey',
])

/**
 * Parse free-text location into city, country, and region.
 *
 * Parsing rules:
 * - The rightmost comma-separated segment is treated as the country or US state.
 * - If that segment is a recognised country or state, the leftmost segment is the city.
 * - If the country/state segment alone would make a single-token location, city is null.
 * - Work-mode words ('remote', 'worldwide', etc.) are stripped from parts; if all segments
 *   are stripped, the result is all nulls with raw preserved.
 * - Parenthesised groups are stripped before parsing, so "(Remote)" suffixes do not corrupt
 *   country/region resolution.
 * - Unparseable input yields all nulls with raw preserved, so no candidate is ever lost
 *   to a parsing failure.
 */
export function normalizeLocation(raw: string | null | undefined): NormalizedLocation {
  if (!raw || !raw.trim()) {
    return { raw: null, city: null, country: null, region: null }
  }

  const trimmed = raw.trim()
  if (NOT_A_PLACE.has(trimmed.toLowerCase())) {
    return { raw: trimmed, city: null, country: null, region: null }
  }

  // Strip parenthesised groups iteratively to handle nesting (e.g., "Cairo, Egypt (Remote)" -> "Cairo, Egypt")
  // Using [^()] instead of [^)] ensures we handle nested parens by stripping innermost first
  let cleaned = trimmed
  while (/\([^()]*\)/.test(cleaned)) {
    cleaned = cleaned.replace(/\s*\([^()]*\)\s*/g, ' ').trim()
  }

  const parts = cleaned
    .split(',')
    .map((part) => part.trim())
    .filter(Boolean)
    .filter((part) => !NOT_A_PLACE.has(part.toLowerCase()))

  if (parts.length === 0) {
    return { raw: trimmed, city: null, country: null, region: null }
  }

  const last = parts[parts.length - 1]

  let country = canonicalCountry(last)
  if (!country && US_STATES.has(last.toLowerCase())) {
    country = 'United States'
  }

  const city = parts.length === 1 && country ? null : parts[0]

  return {
    raw: trimmed,
    city: city ?? null,
    country,
    region: regionForCountry(country),
  }
}
```

```ts
export interface ExperienceEntry {
  title?: string
  company?: string
  from?: string
  to?: string
  durationMonths?: number
}

interface Interval {
  start: number
  end: number
}

const MS_PER_MONTH = (365.25 / 12) * 24 * 60 * 60 * 1000

function parseDate(value: unknown): number | null {
  if (typeof value !== 'string' || value.length === 0) return null
  const time = Date.parse(value)
  return Number.isNaN(time) ? null : time
}

function isEntry(value: unknown): value is ExperienceEntry {
  return typeof value === 'object' && value !== null
}

function mergedMonths(intervals: Interval[]): number {
  if (intervals.length === 0) return 0
  const sorted = [...intervals].sort((a, b) => a.start - b.start)
  let total = 0
  let { start, end } = sorted[0]

  for (const interval of sorted.slice(1)) {
    if (interval.start <= end) {
      end = Math.max(end, interval.end)
    } else {
      total += end - start
      start = interval.start
      end = interval.end
    }
  }
  total += end - start
  return total / MS_PER_MONTH
}

/**
 * Computes total years of professional experience from a candidate's history,
 * merging overlapping employment ranges so concurrent roles are not double-counted.
 *
 * Contract:
 * - Entries with a parseable `from` (and a parseable `to`, or none) become date
 *   intervals and are merged before measuring, so two concurrent or overlapping
 *   roles only count the union of their time, not the sum.
 * - Touching ranges — one range's `to` exactly equal to the next range's `from` —
 *   are merged as continuous employment, not treated as a gap.
 * - Entries carrying only `durationMonths` (no usable dates) are added on top of
 *   the merged date-based total, because without dates there is no way to detect
 *   whether they overlap with anything else.
 * - A missing `to`, or a `to` that cannot be parsed (e.g. "Present", "Current",
 *   or other free text a scraper might emit for an ongoing role), is treated as
 *   "still employed" and measured through to `now`. This is deliberate: the
 *   common real-world case is an ongoing role whose `to` field is exactly such
 *   free text rather than a date.
 * - A reversed or zero-length range (`to` at or before `from`) is nonsense and
 *   contributes no negative interval; it deliberately falls back to that entry's
 *   `durationMonths` if present, otherwise the entry contributes nothing.
 * - A `durationMonths` that is negative, `NaN`, or not a number is silently
 *   ignored. This function never throws and never logs — a scraper producing
 *   bad values simply does not surface here; that is a separate concern.
 * - Robustness against malformed scraper input: `entries` may itself contain
 *   `null`, `undefined`, or other non-object elements (raw scraped JSON is
 *   typed as `any`, so this is genuinely reachable) — such elements are
 *   skipped and the remaining entries are still processed, rather than one
 *   junk element destroying the whole calculation. Likewise, a `from` or `to`
 *   that is not a string (a number, array, object, etc.) is treated as absent
 *   rather than being coerced into a date — coercion can otherwise produce a
 *   bogus interval (e.g. `Date.parse` on a small number resolves to a real,
 *   nonsensical date decades away) instead of leaving the value out.
 * - Returns `null` when there is nothing to measure (no entries, or no entry
 *   yields any usable interval or duration) — never `0` for "no data". A real,
 *   very short tenure (e.g. a two-week contract) can legitimately round to the
 *   number `0`, and that is real data, not "no data". Callers must not treat a
 *   `0` return as absence — conflating the two is the exact bug this module
 *   exists to fix (the current scorer treats a missing value as zero years and
 *   penalises candidates for experience they actually have).
 *
 * @param now - Clock to measure ongoing roles against. Defaults to `new Date()`;
 *   callers that need determinism (tests) should pass a fixed value.
 */
export function totalYearsOfExperience(
  entries: ExperienceEntry[] | null | undefined,
  now: Date = new Date(),
): number | null {
  if (!entries || entries.length === 0) return null

  const intervals: Interval[] = []
  let looseMonths = 0

  for (const entry of entries) {
    if (!isEntry(entry)) continue
    const start = parseDate(entry.from)
    if (start !== null) {
      const end = parseDate(entry.to) ?? now.getTime()
      // A reversed or zero-length range (end <= start) is nonsense — e.g. bad
      // scraper data — and deliberately falls through to the durationMonths
      // fallback below rather than contributing a negative or empty interval.
      if (end > start) {
        intervals.push({ start, end })
        continue
      }
    }
    if (typeof entry.durationMonths === 'number' && entry.durationMonths > 0) {
      looseMonths += entry.durationMonths
    }
  }

  const months = mergedMonths(intervals) + looseMonths
  if (months <= 0) return null
  return Math.round((months / 12) * 10) / 10
}
```

```ts
export type DegreeLevel = 'High school' | 'Diploma' | 'Bachelor' | 'Master' | 'MBA' | 'Doctorate'

export interface EducationEntry {
  school?: string
  degree?: string
  field?: string
  year?: string
}

export interface NormalizedEducation {
  highestDegree: DegreeLevel | null
  fieldsOfStudy: string[]
  schools: string[]
}

// Master and MBA deliberately share a rank: an MBA is a masters-level qualification, but HR
// needs to filter for it specifically, so it is kept as its own DegreeLevel rather than being
// collapsed into 'Master'. On a tie, whichever is encountered first across the entries wins.
const RANK: Record<DegreeLevel, number> = {
  'High school': 1,
  Diploma: 2,
  Bachelor: 3,
  Master: 4,
  MBA: 4,
  Doctorate: 5,
}

const PATTERNS: { level: DegreeLevel; pattern: RegExp }[] = [
  { level: 'Doctorate', pattern: /\b(ph\.?\s?d|doctor(ate)?|dphil)\b/i },
  { level: 'MBA', pattern: /\bm\.?\s?b\.?\s?a\b/i },
  { level: 'Master', pattern: /\b(m\.?\s?sc?|m\.?\s?eng|m\.?\s?a|masters?|master of)\b/i },
  { level: 'Bachelor', pattern: /\b(b\.?\s?sc?|b\.?\s?eng|b\.?\s?a|bachelors?|bachelor of|b\.?\s?tech)\b/i },
  { level: 'Diploma', pattern: /\b(diploma|associate)\b/i },
  { level: 'High school', pattern: /\b(high school|secondary|thanaweya)\b/i },
]

// Field-of-study parsing is split across three pieces that must be kept in sync by hand:
//   - PATTERNS above recognises the degree level from the free-text degree string.
//   - FIELD_ELIGIBLE_LEVELS (below) says at which levels a "field of study" is even a
//     meaningful concept — extend it only when that's true for a newly added level.
//   - GENERIC_FIELD_WORDS (below) catches single-word leftovers of the degree's own name
//     (e.g. stripping "Master of Science" leaves "Science") — extend it if a new pattern's
//     strip leaves behind another generic single word.
// FIELD_ELIGIBLE_LEVELS must stay a subset of the levels present in PATTERNS: fieldFromDegree
// asserts that PATTERNS has an entry for the level, and that assertion is only safe because of
// this (currently unenforced) invariant.
const FIELD_ELIGIBLE_LEVELS: DegreeLevel[] = ['Bachelor', 'Master', 'Doctorate']

// Generic words that are part of a degree's own name, not a field of study — a parsed
// (not explicit) field consisting of exactly one of these words is discarded.
const GENERIC_FIELD_WORDS = new Set([
  'science',
  'arts',
  'letters',
  'philosophy',
  'commerce',
  'technology',
  'studies',
  'general',
  'certificate',
  'honours',
  'honors',
])

function levelFor(degree: string): DegreeLevel | null {
  for (const { level, pattern } of PATTERNS) {
    if (pattern.test(degree)) return level
  }
  return null
}

function fieldFromDegree(degree: string, level: DegreeLevel | null): string | null {
  if (!level || !FIELD_ELIGIBLE_LEVELS.includes(level)) return null
  const stripped = degree
    .replace(PATTERNS.find((p) => p.level === level)!.pattern, ' ')
    .replace(/\b(of|in|degree|honours|honors|hons)\b/gi, ' ')
    .replace(/[.,;()]/g, ' ')
    .replace(/\s+/g, ' ')
    .trim()
  if (stripped.length <= 1) return null
  const words = stripped.split(' ')
  if (words.length === 1 && GENERIC_FIELD_WORDS.has(words[0].toLowerCase())) return null
  return stripped
}

// Adds `value` to `seen`/`order` the first time its lowercased form is encountered, keeping
// the first-seen casing for display while de-duplicating case-insensitively. Fields and
// schools both use this so facet counts don't fragment across "Computer Science" vs
// "computer science".
function addCaseInsensitive(value: string, seen: Set<string>, order: string[]): void {
  const key = value.toLowerCase()
  if (seen.has(key)) return
  seen.add(key)
  order.push(value)
}

/**
 * Derives a highest degree level, distinct fields of study, and distinct schools from a
 * candidate's raw, untrusted education entries.
 *
 * Never throws, and never drops a candidate for having unparsable data:
 *  - `entries` may be null/undefined/empty, and any element of the array that is not a
 *    non-null object (e.g. `null`, a primitive, an array) is skipped rather than crashing
 *    the whole call.
 *  - Within a surviving element, a non-string `school`/`degree`/`field` is treated as absent.
 *  - An explicit `field` on an entry always wins over one parsed from `degree`, and it
 *    bypasses BOTH the field-eligible-level gate and the generic-word stop list — so
 *    `{ degree: 'Diploma', field: 'Certificate' }` yields `fieldsOfStudy: ['Certificate']`
 *    even though 'Diploma' is not field-eligible and "certificate" is itself a stop word.
 *    This is intentional: an explicit field is authoritative, a parsed one is a guess.
 *  - A field is only ever parsed out of the degree string for Bachelor, Master and
 *    Doctorate levels (see FIELD_ELIGIBLE_LEVELS), and a single generic leftover word
 *    (see GENERIC_FIELD_WORDS) is discarded rather than surfaced as a fake field.
 *  - `fieldsOfStudy` and `schools` are both de-duplicated case-insensitively, preserving
 *    the casing of the first occurrence of each value.
 */
export function normalizeEducation(
  entries: EducationEntry[] | null | undefined,
): NormalizedEducation {
  if (!entries || entries.length === 0) {
    return { highestDegree: null, fieldsOfStudy: [], schools: [] }
  }

  let highest: DegreeLevel | null = null
  const fields: string[] = []
  const fieldKeys = new Set<string>()
  const schools: string[] = []
  const schoolKeys = new Set<string>()

  for (const entry of entries) {
    if (typeof entry !== 'object' || entry === null) continue

    const school = typeof entry.school === 'string' ? entry.school.trim() : ''
    const degree = typeof entry.degree === 'string' ? entry.degree.trim() : ''
    const explicitField = typeof entry.field === 'string' ? entry.field.trim() : ''

    if (school) addCaseInsensitive(school, schoolKeys, schools)

    const level = degree ? levelFor(degree) : null
    if (level && (!highest || RANK[level] > RANK[highest])) highest = level

    const field = explicitField || fieldFromDegree(degree, level)
    if (field) addCaseInsensitive(field, fieldKeys, fields)
  }

  return { highestDegree: highest, fieldsOfStudy: fields, schools }
}
```

```ts
export type LanguageLevel = 'Native' | 'Full professional' | 'Professional' | 'Limited' | 'Elementary'

export interface NormalizedLanguage {
  name: string
  level: LanguageLevel | null
}

// Order is load-bearing: levelFor returns the first pattern that matches, so a more specific
// pattern must precede any later pattern whose alternation contains it as a substring (e.g.
// "Full professional proficiency" must match the "Full professional" entry before it ever
// reaches "Professional", whose alternation contains the bare substring "professional").
// LEVEL_PATTERNS must also cover every member of the LanguageLevel union — the two are kept in
// step by hand; adding a level to the union without a corresponding pattern here (in the right
// relative position) leaves that level unreachable.
const LEVEL_PATTERNS: { level: LanguageLevel; pattern: RegExp }[] = [
  { level: 'Native', pattern: /native|bilingual|mother tongue/i },
  { level: 'Full professional', pattern: /full professional|fluent/i },
  { level: 'Professional', pattern: /professional working|professional|advanced/i },
  { level: 'Limited', pattern: /limited working|limited|intermediate/i },
  { level: 'Elementary', pattern: /elementary|basic|beginner/i },
]

export const LANGUAGE_LEVELS: readonly LanguageLevel[] = Object.freeze([
  'Elementary',
  'Limited',
  'Professional',
  'Full professional',
  'Native',
])

function levelFor(value: unknown): LanguageLevel | null {
  if (typeof value !== 'string' || !value.trim()) return null
  for (const { level, pattern } of LEVEL_PATTERNS) {
    if (pattern.test(value)) return level
  }
  return null
}

/**
 * Normalizes a candidate's raw languages data into a de-duplicated list of
 * `{ name, level }` entries.
 *
 * Accepted input shapes: `raw` may be an array whose elements are either
 * bare strings (the language name, with an unknown level), or objects
 * carrying the name under `name` or `language`, and the proficiency under
 * `proficiency` or `level`. Any other input — non-array `raw`, or an array
 * element that is `null`/`undefined`/a primitive/an object without a usable
 * name — is skipped rather than throwing; a non-string `name`/`language` is
 * treated as absent. This function never throws, for any input.
 *
 * De-duplication is by name, case-insensitively, keeping the first-seen
 * casing and the first-seen level for that name. This dedup is scoped to a
 * single candidate's array only: two different candidates may record the
 * same language with different casing (e.g. "English" vs "ENGLISH"), so any
 * cross-candidate aggregation (e.g. a facet count) must also group names
 * case-insensitively, or it will split one language into multiple buckets.
 *
 * A `proficiency`/`level` value that isn't a string, or doesn't match any
 * known LinkedIn proficiency wording, yields `level: null` rather than
 * dropping the entry.
 *
 * `LANGUAGE_LEVELS` lists the possible levels ordered weakest to strongest.
 */
export function normalizeLanguages(raw: unknown): NormalizedLanguage[] {
  if (!Array.isArray(raw)) return []

  const result: NormalizedLanguage[] = []

  for (const entry of raw) {
    let name: string | null = null
    let level: LanguageLevel | null = null

    if (typeof entry === 'string') {
      name = entry.trim() || null
    } else if (entry && typeof entry === 'object') {
      const record = entry as Record<string, unknown>
      const candidate = record.name ?? record.language
      name = typeof candidate === 'string' && candidate.trim() ? candidate.trim() : null
      level = levelFor(record.proficiency) ?? levelFor(record.level)
    }

    if (!name) continue
    if (result.some((existing) => existing.name.toLowerCase() === name.toLowerCase())) continue
    result.push({ name, level })
  }

  return result
}
```

```ts
import industries from '@/data/industries.json'

// Copied into Object.create(null) tables (rather than used as plain JSON objects) so that
// bracket lookups with an attacker/scraper-controlled key such as "constructor" or
// "__proto__" cannot resolve to an inherited value off Object.prototype. See
// src/lib/normalize/regions.ts for the same convention.
const ALIASES: Record<string, string> = Object.create(null)
Object.assign(ALIASES, industries.aliases)

const COMPANIES: Record<string, string> = Object.create(null)
Object.assign(COMPANIES, industries.companies)

const CANONICAL = new Set(Object.values(ALIASES))

/**
 * Canonicalises a candidate's industry into one of the fixed set of names in `INDUSTRIES`,
 * preferring the profile's own stated industry and falling back to a guess from the
 * candidate's current company only when the profile industry is missing or unrecognised.
 *
 * Contract:
 * - `profileIndustry` is looked up (case-insensitively, trimmed) against a hand-curated
 *   alias table; if it doesn't match an alias but is already one of the canonical names
 *   verbatim, that canonical name is returned as-is.
 * - Only when `profileIndustry` yields nothing does `company` get consulted, against a
 *   small table covering the mock/fixture companies only.
 * - Never throws and never returns `undefined`: any input — `null`, `undefined`, a number,
 *   an object, an array, or an empty string, for either argument — is treated as "no data"
 *   and falls through to the next source or to a `null` return. Lookups use own-property
 *   tables (see ALIASES/COMPANIES above) so a key like `'constructor'` or `'__proto__'`
 *   cannot leak an inherited value off `Object.prototype`.
 * - Returns `null` when neither source resolves to a known industry.
 */
export function normalizeIndustry(
  profileIndustry: unknown,
  company: unknown,
): string | null {
  if (typeof profileIndustry === 'string') {
    const raw = profileIndustry.trim().toLowerCase()
    if (raw) {
      const aliased = ALIASES[raw]
      if (aliased) return aliased
      const titled = profileIndustry.trim()
      if (CANONICAL.has(titled)) return titled
    }
  }

  if (typeof company === 'string') {
    const companyKey = company.trim().toLowerCase()
    if (companyKey) {
      const matched = COMPANIES[companyKey]
      if (matched) return matched
    }
  }

  return null
}

export const INDUSTRIES: readonly string[] = Object.freeze(Array.from(CANONICAL).sort())
```

```ts
// `rawItem.<field>` comes straight off an external scraper with no schema guarantee: any of
// these array-shaped fields may be missing, null, or a truthy non-array (a number, a string,
// or a plain object) rather than an array. `(x || []).map(...)` survives null/undefined but
// throws on a truthy non-array, so every array-shaped field is guarded with Array.isArray
// instead. Individual array elements are just as untrustworthy (e.g. `[null]`), so every
// property read off an element below uses optional chaining rather than assuming the element
// itself is a well-formed object.
function asArray(value: unknown): any[] {
  return Array.isArray(value) ? value : [];
}

export function mapToCandidate(rawItem: any): Candidate {
  return {
    externalId: rawItem.id || rawItem.profileUrl,
    fullName: rawItem.fullName || [rawItem.firstName, rawItem.lastName].filter(Boolean).join(" "),
    headline: rawItem.headline,
    currentTitle: rawItem.currentJobTitle || rawItem.currentTitle,
    currentCompany: rawItem.currentCompany,
    location: rawItem.location,
    profileUrl: rawItem.profileUrl || rawItem.url,
    avatarUrl: rawItem.avatarUrl || rawItem.profilePicture,
    summary: rawItem.summary || rawItem.about,
    industry: rawItem.industry,
    skills: asArray(rawItem.skills)
      .map((s: any) => (typeof s === "string" ? s : s?.name))
      .filter((s: unknown): s is string => typeof s === "string"),
    experience: asArray(rawItem.experience).map((exp: any) => ({
      title: exp?.title,
      company: exp?.company,
      durationMonths: exp?.durationMonths,
      from: exp?.startDate || exp?.from,
      to: exp?.endDate || exp?.to,
    })),
    education: asArray(rawItem.education).map((ed: any) => ({
      school: ed?.school,
      degree: ed?.degreeName || ed?.degree,
      field: ed?.fieldOfStudy || ed?.field,
      year: ed?.year,
    })),
    languages: asArray(rawItem.languages),
    certifications: asArray(rawItem.certifications)
      .map((c: any) => (typeof c === "string" ? c : c?.name))
      .filter((c: unknown): c is string => typeof c === "string"),
    totalYearsExperience: rawItem.totalYearsExperience,
    raw: rawItem,
  };
}
```

Third, the same "throws on truthy non-array" defect was found by execution in three of the five sibling modules built in earlier tasks — `normalizeLocation` (`raw.trim()` called without a `typeof raw === 'string'` guard), `totalYearsOfExperience`, and `normalizeEducation` (both did `if (!entries || entries.length === 0)` then `for...of entries`, which throws when `entries` is a truthy non-array such as a number or plain object). All three are hardened the same way: `normalizeLocation`'s parameter is now typed `unknown` with an explicit `typeof raw !== 'string'` check, and the other two now guard with `Array.isArray(entries)` — and, since both now genuinely tolerate any input at runtime, their collection parameters (`entries`) are widened from `EducationEntry[] | null | undefined` / `ExperienceEntry[] | null | undefined` to `unknown` too, so the exported signature is honest about what it accepts (the element types `EducationEntry`/`ExperienceEntry` stay exported unchanged; `Array.isArray` narrows `unknown` to `any[]` for the internal loop, same as the `asArray` helper below). This surfaced while testing `normalizeProfile`'s never-throws guarantee (Step 6) against wrong-typed `Candidate` fields.

`mapToCandidate`'s `languages` field is also routed through the same `asArray` guard as `skills`/`experience`/`education`/`certifications`, rather than the plan's original `rawItem.languages || []` — a non-array `languages` didn't crash only because `normalizeLanguages` happened to guard independently downstream, which is that module's defensiveness, not a guarantee `apify.ts` itself made for a field the whole point of this task was to stop discarding.

- [ ] **Step 6: Write the composed normaliser**

Create `src/lib/normalize/index.ts`. `candidate` is treated as untrusted throughout — every field it reads may be missing, `null`, or the wrong type, since it may come straight from `mapToCandidate`'s `any`-typed input:

```ts
import type { Candidate } from '@/lib/apify'
import { normalizeEducation, type NormalizedEducation } from './education'
import { totalYearsOfExperience } from './experience'
import { normalizeIndustry } from './industry'
import { normalizeLanguages, type NormalizedLanguage } from './languages'
import { normalizeLocation, type NormalizedLocation } from './location'

// export * re-exports every named export from these six modules; TypeScript silently
// drops (rather than errors on) a name exported by more than one of them, so a future
// module added to this directory must keep its exported names unique across all siblings,
// or a collision will fail silently here and surface only as a confusing missing export
// at the consumer's import site.
export * from './education'
export * from './experience'
export * from './industry'
export * from './languages'
export * from './location'
export * from './regions'

export interface NormalizedProfile {
  location: NormalizedLocation
  education: NormalizedEducation
  languages: NormalizedLanguage[]
  industry: string | null
  totalYearsExperience: number | null
}

/**
 * Composes the five sibling normalisation modules into one profile-shaped result.
 *
 * Contract:
 * - Never throws. `candidate` is treated as untrusted: every field it reads
 *   (`location`, `education`, `experience`, `languages`, `industry`, `currentCompany`) may be
 *   missing, `null`, or the wrong type, because it may originate from raw scraper output or
 *   from `mapToCandidate`'s `any`-typed input. Each sibling module is itself defensive against
 *   this, so this function does not add its own guards beyond passing the fields straight
 *   through.
 * - `totalYearsExperience` prefers the value computed from `candidate.experience` (which
 *   merges overlapping roles) over the scraper-reported `candidate.totalYearsExperience`,
 *   and only falls back to the scraper's value when the computation yields `null` (no usable
 *   experience data at all). This ordering is deliberate: the scraper's field is frequently
 *   absent, and treating "absent" as `0` is the exact accuracy bug this normalisation layer
 *   exists to fix.
 *
 * @param now - Clock passed through to `totalYearsOfExperience` for ongoing-role
 *   measurement. Defaults to `new Date()`; callers that need determinism (tests) should pass
 *   a fixed value.
 */
export function normalizeProfile(candidate: Candidate, now: Date = new Date()): NormalizedProfile {
  candidate = candidate ?? ({} as Candidate)
  return {
    location: normalizeLocation(candidate?.location),
    education: normalizeEducation(candidate?.education),
    languages: normalizeLanguages(candidate?.languages),
    industry: normalizeIndustry(candidate?.industry, candidate?.currentCompany),
    totalYearsExperience:
      totalYearsOfExperience(candidate?.experience, now) ?? candidate?.totalYearsExperience ?? null,
  }
}
```

- [x] **Step 1: Harden the Prisma client**

`src/lib/prisma.ts` currently creates a new `PrismaClient` on every module evaluation, which under Next.js hot reload leaks connections, and it does not enable WAL — required for the several-HR-users-at-once case in the spec.

A first version fired `PRAGMA journal_mode = WAL` and `PRAGMA busy_timeout = 5000` at the client without awaiting them and swallowed any failure (`.catch(() => {})`). That is a guarantee that fails silently: if WAL cannot be applied (read-only mount, network share, locked file), the app would run on in rollback-journal mode — precisely what this design says cannot serve concurrent HR users — and nobody would find out. Review caught this; the fixed version applies and verifies WAL synchronously before the app can start, and moves `busy_timeout` to where it actually takes effect. It also rejects a `DATABASE_URL` containing a `?`: SQLite file URLs don't support query parameters, and silently stripping one (e.g. someone copying Postgres's `?connection_limit=1` convention) would silently ignore a deliberately-written setting.

Replace the whole file:

```ts
import { PrismaClient } from '../../generated/prisma/client'
import { PrismaBetterSqlite3 } from '@prisma/adapter-better-sqlite3'
import Database from 'better-sqlite3'

const DATABASE_FILE = process.env.DATABASE_URL?.replace(/^file:/, '') ?? './dev.db'

// Postgres-style connection strings support query parameters; SQLite file URLs do not.
// Silently stripping a deliberately-written setting (e.g. "?connection_limit=1") would be its
// own bug, so refuse to start rather than open a wrongly-named file or a file with a literal
// "?" in its name.
if (DATABASE_FILE.includes('?')) {
  throw new Error(
    `DATABASE_URL "${DATABASE_FILE}" contains a "?" — query parameters are not supported for ` +
      'SQLite connection strings. Remove everything from the "?" onward.',
  )
}

// better-sqlite3 is synchronous, so WAL is applied and verified here, synchronously, at module
// load, using a short-lived direct connection — rather than fired-and-forgotten against the
// adapter's own async connection where a failure (read-only mount, network share, locked file)
// would otherwise go unnoticed and the app would silently run on in rollback-journal mode,
// which cannot serve concurrent HR users. WAL is a persistent property of the database file
// itself, so setting it once here makes it durable for every later connection, including the
// adapter's own.
function ensureWal(file: string): void {
  const db = new Database(file)
  try {
    const mode = db.pragma('journal_mode = WAL', { simple: true }) as string
    if (mode !== 'wal') {
      throw new Error(
        `Failed to enable WAL journal mode on "${file}" (PRAGMA journal_mode reported ` +
          `"${mode}" instead of "wal"). Refusing to start: rollback-journal mode cannot serve ` +
          'concurrent HR users.',
      )
    }
  } finally {
    db.close()
  }
}

ensureWal(DATABASE_FILE)

function createClient() {
  // PrismaBetterSqlite3's config type is better-sqlite3's own `Options & { url }`, and the
  // adapter passes it straight through to `new Database(dbPath, config)` (see
  // node_modules/@prisma/adapter-better-sqlite3/dist/index.js, createBetterSQLite3Client) — so
  // `timeout` here becomes better-sqlite3's busy timeout on the adapter's own connection. This
  // is used in place of a fire-and-forgotten `PRAGMA busy_timeout` statement, since busy_timeout
  // is per-connection and must reach the adapter's own connection to have any effect.
  const adapter = new PrismaBetterSqlite3({ url: `file:${DATABASE_FILE}`, timeout: 5000 })
  return new PrismaClient({ adapter })
}

const globalForPrisma = globalThis as unknown as { prisma?: PrismaClient }

export const prisma = globalForPrisma.prisma ?? createClient()

if (process.env.NODE_ENV !== 'production') {
  globalForPrisma.prisma = prisma
}

// better-sqlite3 is synchronous and single-connection: within this one Node process, queries
// are already serialized, so WAL's benefit here is across *processes* (e.g. this app alongside
// `npm run db:backfill`, or a future second app instance), not within one. Under real
// contention, a query that waits longer than the busy timeout above surfaces to the caller as
// a Prisma "database is locked" error rather than hanging forever.
```

`busy_timeout` route taken: the `timeout` option on `PrismaBetterSqlite3`'s config (typed as better-sqlite3's own `Options & { url }`) is passed straight through to `new Database(dbPath, config)` inside the adapter, so it reaches better-sqlite3's own busy-timeout mechanism directly — no fire-and-forgotten PRAGMA needed for this one.

- [x] **Step 2: Write the backfill script**

`prisma/backfill-normalize-lib.ts`:

```ts
import { normalizeEducation } from '../src/lib/normalize/education'
import { totalYearsOfExperience } from '../src/lib/normalize/experience'
import { normalizeIndustry } from '../src/lib/normalize/industry'
import { normalizeLanguages } from '../src/lib/normalize/languages'
import { normalizeLocation } from '../src/lib/normalize/location'

export function parseJson<T>(value: string | null, fallback: T): T {
  if (!value) return fallback
  try {
    return JSON.parse(value) as T
  } catch {
    return fallback
  }
}

export interface PersonInput {
  id: string
  fullName: string
  raw: string
  locationRaw: string | null
  education: string
  languages: string
  experience: string
  currentCompany: string | null
}

export interface NormalizationUpdate {
  city: string | null
  country: string | null
  region: string | null
  highestDegree: string | null
  fieldsOfStudy: string
  languages: string
  industry: string | null
  totalYearsExperience: number | null
}

/**
 * Pure per-person computation, kept separate from the database loop (in
 * prisma/backfill-normalize.ts) so the per-row failure isolation in runBackfill below can be
 * unit-tested without a real database, and so a throw from here (malformed raw JSON, or a
 * future change to one of the normalize/* modules) is caught per-person rather than aborting
 * the whole run.
 *
 * NOTE: `raw.industry` here and `candidate.industry` in normalizeProfile
 * (src/lib/normalize/index.ts) only agree because the live scrape path stores the full,
 * unmodified raw payload in Person.raw. If that ever changes to a trimmed/projected blob, the
 * two paths diverge and a person's derived industry would depend on which code path last
 * touched them.
 *
 * totalYearsExperience mirrors normalizeProfile's own fallback ordering: prefer the value
 * computed from the structured experience entries (which merges overlapping roles), and only
 * fall back to the scraper's own reported figure (raw.totalYearsExperience) when the
 * computation yields null. Falling back to the *already-stored* column instead would
 * perpetuate exactly the stale/wrong values this backfill exists to correct.
 */
export function computeNormalizationUpdate(person: PersonInput): NormalizationUpdate {
  const raw = parseJson<Record<string, unknown>>(person.raw, {})
  const location = normalizeLocation(person.locationRaw)
  const education = normalizeEducation(parseJson(person.education, []))
  const languages = normalizeLanguages(parseJson(person.languages, []))
  const years = totalYearsOfExperience(parseJson(person.experience, []))
  const industry = normalizeIndustry(raw.industry, person.currentCompany)
  const fallbackYears = typeof raw.totalYearsExperience === 'number' ? raw.totalYearsExperience : null

  return {
    city: location.city,
    country: location.country,
    region: location.region,
    highestDegree: education.highestDegree,
    fieldsOfStudy: JSON.stringify(education.fieldsOfStudy),
    languages: JSON.stringify(languages),
    industry,
    totalYearsExperience: years ?? fallbackYears,
  }
}

export interface BackfillClient {
  person: {
    findMany(): Promise<PersonInput[]>
    update(args: { where: { id: string }; data: NormalizationUpdate }): Promise<unknown>
  }
}

export interface BackfillFailure {
  id: string
  fullName: string
  error: string
}

export interface BackfillResult {
  examined: number
  updated: number
  failed: number
  failures: BackfillFailure[]
}

/**
 * Normalises every person via the injected client.
 *
 * Isolation is per-row: if computeNormalizationUpdate or client.person.update throws for one
 * person, that failure is recorded (with the person's id/name and the error message) and the
 * loop continues with the remaining rows, rather than one bad row aborting the whole backfill.
 * Only when the whole table read (findMany) or something outside the loop throws does the run
 * abort entirely — that is intentional, not this function's job to guard against.
 *
 * Note: this loads the whole table with findMany() and updates row by row. That is fine at
 * HR-sourcing volumes (low hundreds/thousands of people) but is the first thing to change
 * (e.g. batching, or a single SQL UPDATE where possible) if the table ever gets large.
 */
export async function runBackfill(client: BackfillClient): Promise<BackfillResult> {
  const people = await client.person.findMany()
  let updated = 0
  const failures: BackfillFailure[] = []

  for (const person of people) {
    try {
      const data = computeNormalizationUpdate(person)
      await client.person.update({ where: { id: person.id }, data })
      updated += 1
    } catch (error) {
      const message = error instanceof Error ? error.message : String(error)
      failures.push({ id: person.id, fullName: person.fullName, error: message })
      console.error(`failed to normalise person ${person.id} (${person.fullName}): ${message}`)
    }
  }

  return { examined: people.length, updated, failed: failures.length, failures }
}
```

- [ ] **Step 3: Write the implementation**

Create `src/lib/auth/password.ts`. scrypt comes from `node:crypto`, so there is no new dependency, and it is memory-hard which is what you want for stored passwords. `util.promisify`'s typings resolve `scrypt`'s overloads incorrectly, so the promisified function's type is asserted explicitly. An explicit upper bound on the stored `N`/`r`/`p` parameters keeps a corrupted or malicious stored hash from making `verifyPassword` allocate unreasonable memory or block for an unreasonable time — scrypt's memory usage is roughly `128 * N * r` bytes.

```ts
import { randomBytes, scrypt, timingSafeEqual, type ScryptOptions } from 'node:crypto'
import { promisify } from 'node:util'

// `scrypt` is overloaded (with and without an options object) in a way
// `util.promisify`'s typings resolve to the wrong overload, so the options
// form is asserted explicitly here.
const scryptAsync = promisify(scrypt) as (
  password: string | Buffer,
  salt: string | Buffer,
  keylen: number,
  options: ScryptOptions,
) => Promise<Buffer>

const COST = 16384 // N — CPU/memory cost factor
const BLOCK_SIZE = 8 // r — block size
const PARALLELISM = 1 // p — parallelization factor
const KEY_LENGTH = 64

// scrypt's memory usage is roughly 128 * N * r bytes. Cap N so a malicious or
// corrupted stored value can never make verifyPassword allocate an
// unreasonable amount of memory or block the event loop for an unreasonable
// time. The cost this module writes (16384) is comfortably under this.
const MAX_COST = 1 << 20 // 1,048,576
const MAX_BLOCK_SIZE = 1024
const MAX_PARALLELISM = 16

/**
 * Stored hash format: `scrypt$N$r$p$salt$key`, six `$`-separated fields:
 *   1. `scrypt`  — the KDF identifier, so the format can be extended later
 *   2. `N`       — CPU/memory cost factor used to produce this hash
 *   3. `r`       — block size used to produce this hash
 *   4. `p`       — parallelization factor used to produce this hash
 *   5. `salt`    — random per-password salt, base64
 *   6. `key`     — derived key, base64
 * Packing the parameters alongside the salt and hash means the cost can be
 * raised for new passwords later without invalidating hashes already stored
 * with the old parameters.
 */

/**
 * Hashes `password` with scrypt using a fresh random salt.
 * Returns the packed `scrypt$N$r$p$salt$key` string described above.
 * Rejects if `password` is empty. Never throws for a valid non-empty input,
 * though an extremely long password will take proportionally longer.
 */
export async function hashPassword(password: string): Promise<string> {
  if (!password) throw new Error('password must not be empty')
  const salt = randomBytes(16)
  const key = await scryptAsync(password, salt, KEY_LENGTH, {
    N: COST,
    r: BLOCK_SIZE,
    p: PARALLELISM,
  })
  return [
    'scrypt',
    COST,
    BLOCK_SIZE,
    PARALLELISM,
    salt.toString('base64'),
    key.toString('base64'),
  ].join('$')
}

/**
 * Verifies `password` against a `stored` hash produced by `hashPassword`.
 * Always resolves to a boolean — never throws or rejects, even when
 * `stored` is empty, malformed, has non-numeric or implausible parameters,
 * or isn't a string at all — so a corrupted database row can never crash a
 * caller such as a login route. Uses `timingSafeEqual` to compare the
 * derived key against the stored one.
 */
export async function verifyPassword(password: string, stored: string): Promise<boolean> {
  if (!password || !stored || typeof stored !== 'string') return false

  const parts = stored.split('$')
  if (parts.length !== 6 || parts[0] !== 'scrypt') return false

  const [, costRaw, blockRaw, parallelRaw, saltRaw, keyRaw] = parts
  const cost = Number(costRaw)
  const blockSize = Number(blockRaw)
  const parallelism = Number(parallelRaw)
  if (!Number.isInteger(cost) || !Number.isInteger(blockSize) || !Number.isInteger(parallelism)) {
    return false
  }
  if (cost <= 0 || blockSize <= 0 || parallelism <= 0) return false
  if (cost > MAX_COST || blockSize > MAX_BLOCK_SIZE || parallelism > MAX_PARALLELISM) return false

  try {
    const salt = Buffer.from(saltRaw, 'base64')
    const expected = Buffer.from(keyRaw, 'base64')
    if (salt.length === 0 || expected.length === 0) return false

    const actual = await scryptAsync(password, salt, expected.length, {
      N: cost,
      r: blockSize,
      p: parallelism,
    })

    return actual.length === expected.length && timingSafeEqual(actual, expected)
  } catch {
    return false
  }
}
```

```ts
import { createHash, randomBytes } from 'node:crypto'
import { SESSION_TTL_MS } from './constants'

/**
 * Generates a fresh random session token: 32 bytes, base64url-encoded (URL
 * safe, no padding). This is the value that goes in the session cookie. It
 * is never stored — only its hash (see `hashSessionToken`) is persisted.
 */
export function generateSessionToken(): string {
  return randomBytes(32).toString('base64url')
}

/**
 * Deterministically hashes a session token to a 64-character lowercase hex
 * SHA-256 digest. This is what gets stored as `Session.id` in the database,
 * so a leaked database yields no usable session tokens. Never returns the
 * token it was given. Does not throw for an empty string or a non-string
 * input coerced to one.
 */
export function hashSessionToken(token: string): string {
  return createHash('sha256').update(String(token)).digest('hex')
}

/**
 * Returns the instant one session TTL after `now`. `now` defaults to the
 * current time; tests should pass an explicit value for determinism.
 */
export function sessionExpiry(now: Date = new Date()): Date {
  return new Date(now.getTime() + SESSION_TTL_MS)
}

/**
 * Reports whether `expiresAt` is at or before `now`. `now` defaults to the
 * current time; tests should pass an explicit value for determinism. An
 * unparseable `expiresAt` (an invalid Date, e.g. `new Date('nonsense')`)
 * is treated as expired — the safe default for a security check, since
 * `Invalid Date` comparisons are otherwise always `false` and would
 * silently treat a corrupt value as never expiring.
 */
export function isExpired(expiresAt: Date, now: Date = new Date()): boolean {
  if (Number.isNaN(expiresAt.getTime())) return true
  return expiresAt.getTime() <= now.getTime()
}
```

```ts
import { cookies } from 'next/headers'
import { prisma } from '@/lib/prisma'
import { SESSION_COOKIE, SESSION_TTL_MS } from './constants'
import { generateSessionToken, hashSessionToken, isExpired, sessionExpiry } from './token'

export async function createSession(userId: string): Promise<void> {
  const token = generateSessionToken()
  const expiresAt = sessionExpiry()

  await prisma.session.create({
    data: { id: hashSessionToken(token), userId, expiresAt },
  })

  const jar = await cookies()
  jar.set(SESSION_COOKIE, token, {
    httpOnly: true,
    sameSite: 'lax',
    secure: process.env.NODE_ENV === 'production',
    path: '/',
    maxAge: Math.floor(SESSION_TTL_MS / 1000),
  })
}

export async function destroyCurrentSession(): Promise<void> {
  const jar = await cookies()
  const token = jar.get(SESSION_COOKIE)?.value
  if (token) {
    await prisma.session.deleteMany({ where: { id: hashSessionToken(token) } })
  }
  jar.delete(SESSION_COOKIE)
}

export async function destroyAllSessionsFor(userId: string): Promise<void> {
  await prisma.session.deleteMany({ where: { userId } })
}

export interface SessionUser {
  id: string
  email: string
  name: string
  role: string
  mustChangePassword: boolean
}

export async function readSessionUser(): Promise<SessionUser | null> {
  const jar = await cookies()
  const token = jar.get(SESSION_COOKIE)?.value
  if (!token) return null

  const session = await prisma.session.findUnique({
    where: { id: hashSessionToken(token) },
    include: { user: true },
  })

  if (!session) return null
  if (isExpired(session.expiresAt)) {
    await prisma.session.delete({ where: { id: session.id } }).catch(() => {})
    return null
  }
  if (!session.user.isActive) return null

  const { id, email, name, role, mustChangePassword } = session.user
  return { id, email, name, role, mustChangePassword }
}
```

```ts
'use server'

import { redirect } from 'next/navigation'
import { requireUser } from '@/lib/auth/requireUser'
import { hashPassword, verifyPassword } from '@/lib/auth/password'
import { destroyAllSessionsFor, createSession } from '@/lib/auth/session'
import { prisma } from '@/lib/prisma'

export async function changePassword(
  _previous: { error?: string } | undefined,
  formData: FormData,
): Promise<{ error?: string }> {
  const user = await requireUser()
  const current = String(formData.get('current') ?? '')
  const next = String(formData.get('next') ?? '')
  const confirm = String(formData.get('confirm') ?? '')

  if (next.length < 12) return { error: 'Use at least 12 characters.' }
  if (next !== confirm) return { error: 'The two new passwords do not match.' }
  if (next === current) return { error: 'Choose a password you have not used here before.' }

  const record = await prisma.user.findUnique({ where: { id: user.id } })
  if (!record || !(await verifyPassword(current, record.passwordHash))) {
    return { error: 'Your current password is incorrect.' }
  }

  await prisma.user.update({
    where: { id: user.id },
    data: { passwordHash: await hashPassword(next), mustChangePassword: false },
  })

  // Signing every device out after a password change is the point of changing it.
  await destroyAllSessionsFor(user.id)
  await createSession(user.id)
  redirect('/')
}
```

Create `src/proxy.ts`. It sits beside `src/app`, and it must not import the database — the Next.js 16 docs are explicit that proxy runs separately from render code and may be deployed to a CDN. It therefore only checks that a cookie is present; `requireUser()` does the real verification.

```ts
import { NextResponse } from 'next/server'
import type { NextRequest } from 'next/server'
import { PUBLIC_PATHS, SESSION_COOKIE } from '@/lib/auth/constants'

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl

  if (PUBLIC_PATHS.some((path) => pathname === path || pathname.startsWith(`${path}/`))) {
    return NextResponse.next()
  }

  if (request.cookies.has(SESSION_COOKIE)) {
    return NextResponse.next()
  }

  if (pathname.startsWith('/api/')) {
    return NextResponse.json({ error: 'Not signed in' }, { status: 401 })
  }

  const login = new URL('/login', request.url)
  login.searchParams.set('next', pathname)
  return NextResponse.redirect(login)
}

export const config = {
  matcher: ['/((?!_next/static|_next/image|favicon.ico).*)'],
```

```ts
'use server'

import { revalidatePath } from 'next/cache'
import { randomBytes } from 'node:crypto'
import { requireAdmin } from '@/lib/auth/requireUser'
import { hashPassword } from '@/lib/auth/password'
import { destroyAllSessionsFor } from '@/lib/auth/session'
import { ROLES } from '@/lib/auth/constants'
import { prisma } from '@/lib/prisma'

function temporaryPassword(): string {
  return randomBytes(9).toString('base64url')
}

export async function createUser(
  _previous: { error?: string; created?: string } | undefined,
  formData: FormData,
): Promise<{ error?: string; created?: string }> {
  await requireAdmin()

  const email = String(formData.get('email') ?? '').trim().toLowerCase()
  const name = String(formData.get('name') ?? '').trim()
  const role = String(formData.get('role') ?? ROLES.RECRUITER)

  if (!email || !name) return { error: 'Name and email are both required.' }
  if (role !== ROLES.ADMIN && role !== ROLES.RECRUITER) return { error: 'Unknown role.' }
  if (await prisma.user.findUnique({ where: { email } })) {
    return { error: 'That email already has an account.' }
  }

  const password = temporaryPassword()
  await prisma.user.create({
    data: {
      email,
      name,
      role,
      passwordHash: await hashPassword(password),
      mustChangePassword: true,
    },
  })

  revalidatePath('/admin/users')
  return { created: `${email} — temporary password: ${password}` }
}

export async function resetPassword(formData: FormData): Promise<void> {
  await requireAdmin()
  const id = String(formData.get('id') ?? '')
  if (!id) return

  const password = temporaryPassword()
  await prisma.user.update({
    where: { id },
    data: { passwordHash: await hashPassword(password), mustChangePassword: true },
  })
  await destroyAllSessionsFor(id)

  console.log(`[admin] temporary password for ${id}: ${password}`)
  revalidatePath('/admin/users')
}

export async function setActive(formData: FormData): Promise<void> {
  const admin = await requireAdmin()
  const id = String(formData.get('id') ?? '')
  const isActive = String(formData.get('isActive') ?? '') === 'true'
  if (!id || id === admin.id) return // an admin cannot lock themselves out

  await prisma.user.update({ where: { id }, data: { isActive } })
  if (!isActive) await destroyAllSessionsFor(id)
  revalidatePath('/admin/users')
}
```

`resetPassword` writes the temporary password to the server console rather than the page, so it is not left sitting in a browser tab. The admin reads it from the terminal running the app and passes it on.

```ts
  });
```
